# Pinhole calculator

A mobile-first, frontend-only exposure calculator built with Vite, TypeScript, Bulma, and SCSS. Pinhole paper sensitivity is fixed at ISO 6.

## Development

Use Node.js 22.18+ and pnpm.

```sh
pnpm install
pnpm dev
```

```sh
pnpm test
pnpm build
pnpm preview
```

The production build is in `dist/` and can be served by a static host.

## Calculation

`seconds = metered seconds × (pinhole f-number / metered f-number)² × (metered ISO / 6)`

Meter ISO presets range from 25 to 3200 and shutter speeds from 1 second to 1/4000 second, without custom entries. Meter aperture is entered as a positive f-number in a numeric input. Results exclude paper-specific reciprocity correction.

## Architecture

The app is a static TypeScript application with native browser dialogs. No backend or UI framework is required. `index.html` defines the accessible page structure; `src/main.ts` is the composition root that connects the controllers and starts the application.

```text
src/
  main.ts                 Application wiring and startup
  domain/
    exposure.ts           Exposure equation, aperture limits, duration formatting
    exposure.test.ts      Calculation and validation regression tests
  ui/
    calculator.ts         Form state, saved settings, validation and result display
    meter-fields.ts       Meter presets and field construction
    numeric-input.ts      Numeric input restrictions and range clamping
    language.ts           Language selection, translated DOM and persistence
    dialog.ts             Shared animated closing and focus restoration
    dom.ts                Required-element lookup with explicit errors
  formula/
    model.ts              Pure generation of TeX, MathML and accessible descriptions
    model.test.ts         Dynamic values, locales, three-step output and edge cases
    dialog.ts             Formula dialog, render cache and asynchronous update lifecycle
    native.ts             Immediate native MathML rendering
    mathjax.ts            Shared, pinned MathJax loading and configuration
  i18n/
    en.ts, es.ts, eu.ts    Translation dictionaries
    types.ts              Shared language and translation-key types
    index.ts              Locale registry, flags and language validation
  platform/
    storage.ts            Optional localStorage access with failure handling
  styles/
    main.scss             Bulma configuration and stylesheet entry point
    _calculator.scss      Page, calculator and input styles
    _dialogs.scss         Dialogs, formula layout and scrollbar styles
```

### Data flow

1. The language picker reads the saved language. The calculator creates its fields and restores valid saved inputs.
2. Startup applies translations and asks the calculator to update.
3. Input changes read the current settings, validate the meter aperture, calculate exposure and update the result. The same settings are passed to the formula controller, and input values are saved.
4. The formula model derives all three worked-example rows from the current settings. Display rounding never feeds back into the exposure calculation.
5. Native MathML renders immediately. MathJax loads in the background from the pinned jsDelivr URL and enhances the formulas with SVG. Updates carry a revision number so stale asynchronous results are discarded. If the modal is open, enhancement waits until it closes to avoid changing typography while it is being read.

The domain and formula model are independent of browser APIs and can be tested in Node. Controllers own DOM events and local state; they communicate through callbacks wired in `main.ts`. Storage and MathJax access are isolated at the browser boundary. There is no application-wide event bus or state library.

### Languages and persistence

Spanish, Basque, and English each have a dictionary in `src/i18n/`. English defines the required keys; TypeScript checks the other dictionaries against that contract. Static labels use `data-i18n`, while calculated formula content is generated by the formula model.

The first visit opens the language dialog. The selected language is stored under `pinhole-language`; calculator inputs use `pinhole-settings`. Invalid saved inputs are ignored, and blocked storage does not prevent the app from working. Flag SVGs are bundled in `public/flags/`.

### Rendering and verification

MathJax is an optional external enhancement: native MathML remains available if its CDN fails. Both renderers retain the centered three-row example, emphasized final line and accessible description.

`pnpm test` runs domain and formula-model tests; `pnpm build` checks application types and creates `dist/`. These checks do not replace browser verification of mobile layout, keyboard focus, scrolling or MathJax loading. When changing those behaviors, check the modal at narrow widths, switch all three languages, reopen it after changing settings, and try with the CDN blocked.
